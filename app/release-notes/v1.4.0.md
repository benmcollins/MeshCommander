# QuMesh 1.4.0

A small follow-up to 1.3.0 that adds an encrypted backup format for
the machine list and fixes a noisy QML warning in the main list.

## Encrypted backup / restore of the machine list

The title bar grew two new buttons: **Export** writes the entire
machine list — including stored credentials — to a single
`.qumesh-backup` file sealed under a password, and **Import** reads
one back.

- The file format is AES-256-GCM under a PBKDF2-HMAC-SHA256-derived
  key (600 000 iterations, 32-byte salt, 12-byte IV, 16-byte tag).
  Wrong password, tampered ciphertext, and malformed envelope are
  distinguished so the UI can show the right error.
- Import previews a **"N new, M updated"** diff before applying. Rows
  are matched by stable id first, then by `(host, name)`, so a
  renamed machine merges instead of duplicating.
- Plan entries carry the target's id (not its row index), so a
  model edit between **Preview** and **Apply** can't silently
  overwrite an unrelated row.
- Decode rejects files larger than 64 MiB, KDF costs above 10 M
  iterations, and passwords longer than 1024 chars — so a hostile
  file can't freeze the UI thread inside PBKDF2.
- Secrets travel in plaintext inside the GCM envelope (the per-install
  v3 `SecretCodec` key doesn't survive a transfer); the local
  keystore re-wraps them on apply.

New tests cover round-trip, wrong password, truncated file, unknown
type / version, tampered ciphertext, envelope-header validation, the
size / cost / password caps, and the id-re-resolution at apply time
(regression test for the matched row being deleted mid-confirm).

## Fix: noisy QML warnings on the main computer list

The `populate` and `add` transitions in `ComputerListView.qml` read
`ViewTransition.index` / `ViewTransition.item` unqualified from inside
their inner animations. That attached property lives on the enclosing
`Transition`, not on the animations, so the lookups resolved to
`undefined` / `null` and produced these warnings on every launch:

```
QML PauseAnimation: Cannot set a duration of < 0
TypeError: Cannot read property 'y' of null
```

The transitions now reach through their own ids
(`populateTrans.ViewTransition.…`, `addTrans.ViewTransition.…`),
matching the pattern in the official Qt docs. Behaviour is
unchanged — same stagger, same fade/slide.

## Upgrading

- **macOS** — `Check for Updates…` from the QuMesh menu, or grab the
  `.dmg` from the Releases page.
- **Windows** — `Check for Updates…` from the menu, or download the
  `.exe` from Releases.
- **Linux** — `sudo apt update && sudo apt upgrade qumesh` if you've
  added the repo (snippet in the v1.2.0 notes). Otherwise grab the
  `.deb` matching your distro / architecture from the Releases page;
  arm64 is supported on both Debian 13 and Ubuntu 26.04.
